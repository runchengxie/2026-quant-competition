# 任务产物保留

[English](artifact-retention.md) · [文档目录](../README.zh-CN.md)

每项任务收尾时，在选定项目根目录的 `retention/<review-date>/` 保存明确清单。全新安装使用 `DATA_ROOT/global-market-research`，只有旧目录的安装在[完成有记录的迁移](data-root-migration.zh-CN.md)前继续使用旧目录。清单留在私人数据目录。公共 Git 只保存本规则和复现说明，不保存私人产物、机器路径或策略参数。从明确提供的工作区配置或环境变量解析根目录；任务 worktree 使用所属仓库的永久数据目录。

## 保留决定

| 分类 | 默认决定 | 所需依据 |
| --- | --- | --- |
| 原始输入和获取回执 | 保留 | 保存来源和权威所有者，共享数据留在提供方目录 |
| 版本化研究结果、协议、清单和账本 | 保留 | 保存版本及输入输出关系，包括已被替代的结果 |
| 验证日志、验收证据和恢复材料 | 保留 | 保存交付记录及理解、恢复证据所需的材料 |
| broker 环境和运行状态 | 保留 | 另行开展运行审查，本规则不授权 broker 或生产变更 |
| 未识别内容或消费者尚未查明 | 保留待审 | 记录未知事项和复查触发条件，名称和时间不能证明任务完成 |
| 任务专用虚拟环境和带锁文件的前端依赖 | 有条件的退役候选 | 任务完成证据、所属提交、锁文件、重建命令、包版本记录及下列检查 |
| 真正的任务专用 uv 缓存 | 有条件的退役候选 | 确认真正的 uv 缓存归属和范围，核对消费者，使用 uv 支持的维护命令 |

名为 `cache` 的目录可能保存输入或独有研究证据，不能按名称判定可删。任务已合并或目录带日期，也不能证明产物没有消费者。当前使用的研究环境和 broker 相关环境继续保留，直至另行审查有充分依据。

## 任务收尾

1. 记录任务 ID、所属仓库和提交、完成证据、产物路径、分类、决定、依据、消费者引用和复查触发条件。考虑退役可重建依赖前，先记录锁文件标识和准确安装命令。
2. 盘点链接、目录联接、清单及 `current`/`latest` 别名，包括使用这些名称的普通文件。核对目标和下游引用。清理时不遍历未知链接；引用未查明就保留。
3. 退役依赖前，检查运行进程、计划任务、启动器、活动 worktree 和下游用户，记录检查时间与范围。检查不可用或不完整就保留待审。盘点不停止进程，不修改任务。
4. 后续任务将保留证据与可重建依赖分目录存放，使用任务专用输出路径。共享指针仅通过协调后的发布流程更新，不复制权威数据集。
5. 如另行获准退役，记录准确路径、操作前后结果和重建说明，更新私人清单并保留旧回执。保留审查本身不删除、不迁移、不设置自动过期或调度。

使用小型 CSV 或 JSON 清单加简短报告即可。建议字段为 `path`、`owner_commit`、`category`、`decision`、`basis`、`consumers`、`rebuild`、`unknowns`、`review_trigger` 和 `reviewed_at`。复查可由任务验收、消费者迁移或下次复现请求触发，不代表自动删除日期。根清单覆盖所有顶层条目，任务清单记录明确例外。目录保留决定覆盖后代，除非另有审查通过的例外。

私人报告应区分本次观察、此前清理回执与未决问题。不重复删除已经退役的依赖，也不只靠旧回执推断现状。本规则不改变交易或研究行为，不证明实盘连接已就绪。
