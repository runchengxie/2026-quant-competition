# GitHub Pages content policy

The public site is built only from the reviewed files under `site/`. The workflow must never copy repository documentation, research outputs, run directories, release assets, or generated execution artifacts into the Pages artifact.

## Allowed

- A high-level project introduction and system architecture.
- A link to the official public competition rules and public repository.
- Current public competition dates, labeled with the official source date.
- Sanitized, reproducible historical or Paper results only after source, period, fees, benchmark, and execution status have been reviewed.
- A clear statement that results are not available for publication when no result passes that review.

## Prohibited

- API keys, tokens, passwords, private keys, environment files, account identifiers, order IDs, and broker connection details.
- Current positions, orders, account balances, live performance, raw market/provider data, or provider responses.
- Exact private model parameters, unreviewed run artifacts, or copies of team-only competition materials.
- Any claim that a strategy is registered, validated, or executed in Paper unless the supporting approval and evidence exist.

Changes to site content require a manual review of the rendered page and its linked sources. The content check is a guardrail, not a replacement for review.
